# Build and release

The project builds with the Gradle wrapper. Android Studio is not required at any point.

## Verified toolchain

This exact combination was built, tested and linted locally, producing an installable APK:

| Component | Version | Note |
| --- | --- | --- |
| Gradle | 8.14.6 | via the committed wrapper |
| Android Gradle Plugin | 8.13.2 | |
| Kotlin | 2.4.21 | with the Compose compiler plugin |
| Compose BOM | 2026.06.01 | see the pinning note below |
| JDK | 21 (Temurin) | both locally and in CI — Robolectric's SDK 36 image needs 21 |
| compileSdk / targetSdk | 36 | |
| minSdk | 26 | Android 8.0 |
| Android SDK | `platforms;android-36`, `build-tools;36.0.0` | installed via `cmdline-tools` |

**Why the dependencies are pinned below the newest release.** `core-ktx:1.19.1` and every
Compose artifact from BOM `2026.09.00` onward declare `minCompileSdk=37` and require AGP
9.1+. AGP 8.13.2 supports `compileSdk` 36 at most, so the newest self-consistent set that
works on AGP 8.x is the one above (`core-ktx:1.18.0`, BOM `2026.06.01`). Lint will report
"a newer version is available" for each of these — that warning is expected and upgrading
requires moving to AGP 9.x, which is a deliberate, separate change.

## What the build needs

- **JDK 17 or newer.** JDK 21 is what this project was verified against locally.
- **Android SDK** with `platforms;android-36` and `build-tools;36.0.0`. The SDK can be
  installed from the command line with Google's `cmdline-tools` — no IDE needed:

  ```powershell
  # once
  $root = "$env:USERPROFILE\android-sdk"
  # download https://dl.google.com/android/repository/commandlinetools-win-11076708_latest.zip
  # extract it so that "$root\cmdline-tools\latest\bin\sdkmanager.bat" exists, then:
  sdkmanager --sdk_root="$root" --licenses
  sdkmanager --sdk_root="$root" "platform-tools" "platforms;android-36" "build-tools;36.0.0"
  ```

- **`local.properties`** in the project root pointing at that SDK (git-ignored):

  ```properties
  sdk.dir=C\:\\Users\\<you>\\android-sdk
  ```

## Local build

```powershell
.\gradlew.bat testDebugUnitTest   # JVM unit tests
.\gradlew.bat assembleDebug       # APK
```

On macOS/Linux use `./gradlew` instead. The APK lands at:

```
app/build/outputs/apk/debug/app-debug.apk
```

To produce the same predictable path the CI uses:

```powershell
New-Item -ItemType Directory -Force dist | Out-Null
Copy-Item app/build/outputs/apk/debug/app-debug.apk dist/ZendoLauncher-debug.apk
```

## Remote build (the primary path)

`.github/workflows/build-apk.yml` builds the APK on a GitHub-hosted runner, so the only
thing the user needs is a browser.

**Run it manually:** repository → **Actions** → **Build APK** → **Run workflow** →
choose `debug` or `release` → **Run workflow**.

It also runs automatically on every push to `main`.

**Download the APK:** open the completed run and take the artifact named
`zendo-launcher-<variant>-<commit sha>`. The run summary also prints the variant,
version, byte size and SHA-256 of the staged APK. Artifacts are kept for 30 days; test
and lint reports for 14.

The workflow stages the APK at `dist/ZendoLauncher-debug.apk` (or
`dist/ZendoLauncher-release-unsigned.apk`) before uploading, and fails the run if the
expected file is missing or is not a valid ZIP containing `AndroidManifest.xml` — a
green run means a real APK exists, not just a successful compile step.

## Debug vs release

| | debug | release |
| --- | --- | --- |
| Signing | Android debug key, generated by the toolchain | Your own keystore, only if configured |
| Package id | `com.zendolauncher` | `com.zendolauncher` |
| Version name | `0.2.2-debug` | `0.2.2` |
| Use | device testing, sideloading | distribution |

**No signing material is committed.** `*.keystore`, `*.jks` and `keystore.properties` are
git-ignored.

To build a signed release, add these repository secrets and the workflow will use them:

| Secret | Meaning |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | base64 of your `.jks` (`base64 -w0 release.jks`) |
| `ANDROID_KEYSTORE_PASSWORD` | keystore password |
| `ANDROID_KEY_ALIAS` | key alias |
| `ANDROID_KEY_PASSWORD` | key password |

`app/build.gradle` only reads `keystore.properties` when the file exists, so an
unconfigured checkout still builds; it simply produces an unsigned release APK.

Pushing a tag matching `v*` triggers the release job. With secrets configured it builds
the signed APK and attaches it to a GitHub Release. Without them it fails loudly with an
explanatory message rather than publishing anything — an unsigned APK is not shipped as
if it were a release.

### The `debug-*` pre-releases

The downloads linked from the README are not produced by that job. They are **debug
pre-releases**, tagged `debug-<version>` (for example `debug-0.2.2`), and they are created
by hand rather than by the workflow:

1. Push to `main` and let the `build` job finish. It uploads the debug APK as a workflow
   artifact, named `zendo-launcher-debug-<sha>`.
2. Download that artifact and confirm it is the build you mean to publish — read the
   version out of the APK rather than trusting the file name.
3. Create the release as a pre-release, tagging it `debug-<version>`, with the APK
   attached.

A `debug-*` tag does not match `v*`, so it deliberately does not trigger the release job,
and the signing secrets play no part in it. The APK is signed with the Android debug key,
which is why these are marked pre-release and why Android warns about an unknown source on
install. The debug key is stable across builds, so a new `debug-*` build installs over the
previous one as long as `versionCode` was raised.

Nothing here publishes a signed release. Only the `v*` job does that, and only with the
secrets configured.

## Versioning

`versionCode` and `versionName` are set in `app/build.gradle` under `defaultConfig`.
Bump both before a release. Future updates must be signed with the **same** keystore as
the installed build, or Android will refuse to update over it.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| `SDK location not found` | Create `local.properties` with `sdk.dir=...`, or set `ANDROID_HOME`. |
| `Failed to install the following SDK components` | Run the two `sdkmanager` commands above; accept licences. |
| `Unsupported class file major version` | Gradle is running on a JDK that is too old. Use JDK 17+. |
| Workflow fails at `Stage APK into dist/` | The variant produced no APK; the step prints what it found under `app/build/outputs`. |
| Workflow release job fails with a signing error | Expected until the four secrets exist. Use the debug artifact meanwhile. |
| Build hangs on first run | Gradle is downloading the 8.14.6 distribution and dependencies. |
